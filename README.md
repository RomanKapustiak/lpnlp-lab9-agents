# Універсальний ReAct-агент з Canvas і Deep Research

**Задача.** Універсальний асистент, який сам вирішує, якими інструментами скористатися: дізнатися погоду,
курс валют, прочитати сторінку, знайти інформацію в інтернеті або провести глибоке дослідження.
Результати можна оформити як документ у «Canvas» (за аналогією з Canvas у ChatGPT): документ видно поруч
із чатом, його можна правити повідомленнями, вставляти інтерактивні графіки та завантажувати як **PDF**.

**Стек:** Google ADK (`google-adk`) + Gemini, Streamlit, Langfuse, Plotly / matplotlib, fpdf2.

## Архітектура

```
assistant (LlmAgent, ReAct: міркування → виклик інструмента → спостереження → …)
│  системний промпт генерується перед кожним викликом моделі: дата/час (Europe/Kyiv) + стан Canvas
│
├── get_weather(city, days)                     — Open-Meteo: поточна погода і прогноз до 16 днів
├── get_exchange_rate(currency, start, end)     — офіційний курс НБУ на дату або за період
├── search_web(queries, max_results, time_range) — пошук в інтернеті (DuckDuckGo, без ключа)
├── fetch_url(url, max_chars)                   — текст вебсторінки (блокує приватні IP)
├── make_line_chart(title, x, series, ...)      — лінійний графік: Plotly (hover) у Canvas, PNG у PDF
├── create_report(title, markdown)              — Canvas: створює документ → PDF
├── edit_report(edits, new_title)               — Canvas: точкові правки документа
│
└── deep_research = AgentTool(LlmAgent)         — під-агент глибокого дослідження (теж ReAct)
       вхід: ResearchPlan {goal, context, sub_questions, search_hints, constraints, output_format}
       інструменти: search_web + fetch_url
       шукає → читає джерела → оцінює прогалини → шукає ще … → сам вирішує, що досить
       вихід: звіт з висновками по підпитаннях і списком джерел (URL)
```

### Структура коду
```
app.py               — сторінка Streamlit і запуск одного ходу агента (цикл подій ADK → кроки в чаті)
agent/
  agents.py          — збирання агентів: головний ReAct-агент + deep_research як інструмент
  prompts.py         — системні промпти (функції, що додають дату/час і стан Canvas)
  tools.py           — погода, курс НБУ, пошук в інтернеті, читання сторінок
  canvas.py          — графіки і документ (make_line_chart, create_report, edit_report)
  render.py          — Plotly-графік для застосунку, PNG-графік і PDF для завантаження
  ui.py              — відображення повідомлень, кроків агента і Canvas
  tracing.py         — Langfuse
  config.py          — список моделей, ключ з .env, константи
```

### Як реалізовано ReAct
Головний агент — `LlmAgent` ADK з увімкненим thinking (`include_thoughts=True`). Цикл ReAct виконує ADK:
модель міркує (*Reason*), викликає інструмент (*Act*), отримує результат (*Observation*) і вирішує, що робити
далі, доки не дасть фінальну відповідь. `Runner.run_async` повертає подію на кожен крок, і `app.py` показує їх
у чаті: «Міркування», блок кожного інструмента (аргументи + результат) і відповідь.

Інструменти — звичайні Python-функції: ADK будує JSON-схему з їхньої сигнатури та docstring. Помилка
в будь-якому інструменті не обриває хід: `on_tool_error_callback` повертає її моделі як результат,
і модель може виправитися (наприклад, повторити `make_line_chart` з правильною кількістю значень).

### Agent as a tool
**deep_research.** Головний агент передає не один запит, а **структурований план дослідження**
(pydantic-схема `ResearchPlan` стає схемою аргументів інструмента). Всередині — окремий ReAct-агент
зі своїм промптом та інструментами `search_web` і `fetch_url`: він шукає, читає сторінки, після кожного
кроку оцінює, на які підпитання ще немає відповіді, і сам вирішує, коли інформації досить.
Від надмірних витрат захищає бюджет (до 4 викликів `search_web` і 8 `fetch_url`, перевіряється
в `before_tool_callback`). Головний агент отримує лише підсумковий звіт із джерелами, тому проміжні
результати пошуку не займають його контекст.

### Моделі і пошук
Усі агенти працюють на моделі Gemini, обраній у боковій панелі. Пошук — звичайна функція `search_web`
на DuckDuckGo, а не вбудований Google Search у Gemini: grounding має окрему квоту, яка на безкоштовному
ключі мала (а для моделей Gemini 3+ на Free-тарифі недоступна).

### Спостережуваність (Langfuse)
Якщо задані `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` і `LANGFUSE_BASE_URL`, кожен хід чату пишеться в
Langfuse як окремий трейс: агенти, кожен LLM-виклик (модель, токени, промпт і відповідь) та кожен
виклик інструмента, включно з вкладеним запуском `deep_research`. Трейси однієї розмови
об'єднуються в сесію. Спани ADK збирає `openinference-instrumentation-google-adk` (OpenTelemetry), а Langfuse
SDK їх експортує. Під кожною відповіддю в чаті є посилання на її трейс.

### Canvas
Графіки і документ зберігаються у state сесії ADK (`state["charts"]`, `state["report"]`), тому
переживають ходи розмови, а промпт агента щоразу містить поточний текст документа.
- `make_line_chart` повертає placeholder `[[chart:chart_1]]`, який агент вставляє в Markdown документа;
  з `replace_chart_id` графік оновлюється на місці (наприклад, додати ще одну валюту).
- `create_report` рендерить **PDF** через fpdf2 (шрифт DejaVu з кирилицею, графіки — PNG із matplotlib).
- У застосунку документ показується з інтерактивними Plotly-графіками (hover, zoom).
- `edit_report` дозволяє правити документ точково («скороти висновок», «додай розділ про ризики»).

## Запуск локально

```bash
pip install -r requirements.txt
streamlit run app.py     # http://localhost:8501
```

API-ключ Gemini ([Google AI Studio](https://aistudio.google.com/apikey)) вводиться в інтерфейсі
й не зберігається. Для локальної розробки ключ можна покласти в `.env` поруч з `app.py`
(`GEMINI_API_KEY`, `LANGFUSE_*`); цей файл не потрапляє в git.
На HF Spaces ключі Langfuse задаються як Secrets Space.

**Деплой на HF Spaces:** Space з SDK *Streamlit*; у репозиторій Space завантажити `app.py`,
папку `agent/`, `requirements.txt`, `README.md` (YAML-блок на початку README задає SDK і версію Streamlit).
